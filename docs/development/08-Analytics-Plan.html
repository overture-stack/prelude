Here is a short plan for adding web analytics (Google Analytics 4 through Google Tag Manager) to the data portal. It covers the metrics you asked about plus a few low cost additions, reported monthly.

1. Metrics

MetricDefinitionHow it is captured
Unique visitors per month Distinct users in the period (GA4 Active Users), including new vs. returning and country or region (Canada vs. international uptake, useful for grant reporting). GA4 automatic, no extra code
Monthly downloads Count of dataset export actions, broken down by download type (Metadata only vs. Metadata + File manifest) and result set size. Custom event on the download button
Session data
  • Time per session
  • Facet or filter interactions per session
  • Did the session end in a download?
This lets us assess the search to download conversion rate, the percentage of querying sessions that download. Did people find what they came for, and how long did it take?

Query depth per session: the number of filters applied before download or exit (shallow vs. deep exploration).

Most used facets: which filters (for example diagnostic target, collection device, sequencing instrument) drive discovery, so curation decisions follow what users actually query.

 Custom events on facet interactions, joined to downloads

2. Events to capture

GA4 standard reports should cover the metrics above automatically [please confirm]. The portal specific value comes from a small set of custom events.

EventTriggerKey details
file_download Click on a download button, covering both menu options (Metadata only, Metadata + File manifest) download type, result count, selected rows, active filter count
facet_filter A facet value is selected or deselected facet field, add or remove, result count
explorer_view Data explorer page or tab loaded explorer name (clinical, molecular, and so on)

Because every facet and download event shares the same session ID, query volume and downloads can be paired per session for the conversion funnel, with no need to send them together.

Privacy: we send aggregate values only (counts, field names, download type). We never send raw query values, sample IDs, or anything that identifies a user.

3. Implementation notes

  • Page views: the portal is a single page app, so we add a route change listener that records each move between explorer pages.
  • Download: hook the existing download button to send a file_download event tagged with which menu option was chosen.
  • Facets: hook the facet panel to send a facet_filter event on each change.
  • Zero results (optional): record when a query returns no rows, which flags data gaps and friction.

4. Consent and compliance

  • Canadian deployment, so we align with PIPEDA: a lightweight cookie consent banner with analytics gated behind consent.
  • Enable IP anonymisation and disable advertising features.
  • Document the analytics in the portal privacy policy.

5. Reporting

  • A GA4 dashboard plus a monthly export for grant records.
  • Headline figures: unique users, sessions, downloads by type, search to download conversion, top facets, and geography.
